# Agile Planning with GitHub Projects (Kanban)

## Description
Ce projet démontre l’utilisation de GitHub Projects pour mettre en place un tableau Kanban Agile permettant de gérer efficacement le cycle de vie des tâches d’un projet logiciel.

L’objectif est de montrer la capacité à :
- organiser le travail selon une approche Agile
- utiliser GitHub Projects comme outil de gestion de projet
- structurer un backlog, un sprint et le suivi d’avancement

---

## Objectifs du projet
- Mettre en place un Kanban board fonctionnel
- Gérer un Product Backlog et un Sprint Backlog
- Suivre l’avancement des tâches de New à Done
- Illustrer une méthodologie Agile claire et structurée

---

## Outils et technologies
- GitHub Projects
- GitHub Issues
- Méthodologie Agile / Kanban

---

## Structure du Kanban
Le tableau GitHub Projects est structuré avec les colonnes suivantes :

- New issues : tâches nouvellement créées
- Icebox : idées ou tâches non prioritaires
- Product Backlog : tâches validées à réaliser
- Sprint Backlog : tâches planifiées pour le sprint en cours
- In progress : tâches en cours de développement
- Review / QA : tâches en cours de revue ou de validation
- Done : tâches terminées

---

## Exemples de fonctionnalités gérées
- Incrémentation d’un compteur
- Réinitialisation d’un compteur
- Persistance des données
- Déploiement du service dans le cloud

Chaque fonctionnalité est représentée par une issue GitHub et suivie tout au long du workflow Kanban.

---

## Workflow Agile
1. Création d’une issue
2. Ajout au Product Backlog
3. Planification dans un Sprint
4. Passage en In progress
5. Revue et QA
6. Validation en Done

---

Ce projet met en avant :
- la gestion de projet Agile

- le suivi du delivery de bout en bout
